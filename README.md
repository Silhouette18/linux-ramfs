# Custom RAM File System (Linux Kernel Module)

A custom, fully functional Linux file system that lives entirely in RAM (Random Access Memory), written in C. 

This project is implemented as a loadable Linux kernel module. Because it lives in RAM, read and write operations are incredibly fast. It demonstrates a deep understanding of the Linux Virtual File System (VFS) layer, kernel memory management, and how the Linux kernel handles files, directories, and inodes.

## Architecture
The file system is broken down into modular components, mirroring standard Linux kernel design:

* **`super.c`**: Handles mounting, unmounting, and registering the file system with the kernel. It defines the superblock, which represents the file system as a whole.
* **`inode.c`**: Manages inodes (the metadata structures that represent files and directories). Handles operations like creating files, looking up files, and allocating memory.
* **`file.c`**: Defines the file operations (like `read`, `write`, `open`, and `llseek`) mapping user-space actions to kernel-space execution.
* **`ramfs.h`**: The main header file containing custom data structures, macros, and function prototypes.
* **`Makefile`**: Configured to build the project against the Linux kernel build tree.

## Prerequisites
To compile and run this, you must be on a Linux system (preferably a Virtual Machine) with the kernel headers installed:
```bash
sudo apt-get install build-essential linux-headers-$(uname -r)
```

## Getting Started

### 1. Compile the Module
Use the provided Makefile to compile the kernel module:
```bash
make
```
This will generate a `.ko` (Kernel Object) file.

### 2. Load the Module
Insert the compiled module into the Linux kernel:
```bash
sudo insmod my_ramfs.ko
```
*(Note: Replace `my_ramfs.ko` with the actual output name generated by the Makefile).*

You can verify it was loaded by checking the kernel logs:
```bash
dmesg | tail
```

### 3. Mount the File System
Create a mount point and mount your new RAM file system to it:
```bash
sudo mkdir -p /mnt/ramfs
sudo mount -t my_ramfs none /mnt/ramfs
```

### 4. Test it out!
You can now treat `/mnt/ramfs` like a normal folder, except everything is happening in your custom RAM file system:
```bash
cd /mnt/ramfs
echo "Hello from RAM!" > test.txt
cat test.txt
ls -la
```
*(Note: Because this file system lives in RAM, all data will be destroyed when unmounted or when the system reboots).*

### 5. Unmount and Cleanup
When you are done, unmount the file system and remove the module from the kernel:
```bash
cd ~
sudo umount /mnt/ramfs
sudo rmmod my_ramfs
```

## Warning
Because this code runs in **Kernel Space**, a bug can cause a kernel panic and crash the operating system. It is highly recommended to test this module inside a Virtual Machine rather than on your main host machine.
